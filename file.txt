Problem Statement 2: AI Agentic Honeypot for Scam Intelligence

Background
Scam messages (SMS, WhatsApp, Telegram) are rampant. Instead of just blocking them, law enforcement agencies want to gather intelligence. An "AI Honeypot" can pretend to be a victim, engage the scammer, and extract valuable data (UPI IDs, crypto wallets, phone numbers, fake URLs) to report them.

Your Task
Build an API that acts as this honeypot.
1. The API receives an incoming message (simulating a scammer).
2. It detects if the message is a scam.
3. If it is a scam, an AI agent takes over (e.g., pretending to be a naive user) and generates a reply to keep the scammer hooked.
4. As the conversation progresses, the agent extracts intelligence (payment details, links).
5. Finally, the system reports this intelligence back to a central endpoint.

Key Requirements
1. Scam Detection: Use an LLM or classification logic to decide if the message is a scam.
2. Agent Persona: The AI should act like a realistic victim (e.g., elderly person, greedy investor) to prolong the chat.
3. Intelligence Extraction: Identify and save:
   - UPI IDs (e.g., scammer@upi)
   - Crypto Wallet Addresses
   - Phishing Links
   - Phone Numbers
4. Final Reporting: Send the gathered data to the provided GUVI API endpoint.

Deliverable Endpoint
You must expose a POST endpoint (e.g., /chat or /webhook).
GUVI’s system will send messages to your endpoint to test your agent.

Reporting API (To be called by your system)
URL: https://hackathon.guvi.in/api/updateHoneyPotFinalResult
Method: POST
Headers: Content-Type: application/json

Payload Schema:
{
  "scammerId": "string (The sender's phone number or ID)",
  "scamType": "string (e.g. Financial, Crypto, Job Scam)",
  "evidence": {
    "chatHistory": [
      { "role": "scammer", "content": "..." },
      { "role": "agent", "content": "..." }
    ],
    "extractedIntelligence": {
      "upi": ["..."],
      "crypto": ["..."],
      "urls": ["..."]
    },
    "agentNotes": "string (Brief summary of what happened)"
  }
}
